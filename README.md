# 像素秘境 · Pixel Rogue

一款 PC 浏览器优先的 2D 像素动作割草 Roguelike：移动躲避敌人，角色自动攻击，通过升级、天赋与属性搭配自己的玩法。

项目使用 **TypeScript + Vite + Phaser 4**，可以部署为静态网站，无需后端或数据库。当前保留射手 / 法师 / 战士职业专属卡池与通用卡（旧表 39 张已于 v165 删除）、13 条敌人图鉴（10 种普通 / 特殊怪 + 裂胶子体 + 岩石巨兽精英 + 三首巨兽首领）、波次休整、升级三选一、卡片刷新、伤害报告与本地战绩；规则对照基线为 `legacy/upstream-v8.html`（`27565b4`）。

**这份说明也面向不熟悉编程、主要借助 AI 协作的朋友。** 不必先学会全部技术；先把项目运行起来，再按下文模板让 AI 完成一项明确任务。

## 1. 准备环境与项目

### 1.1 安装哪些软件

Windows 推荐准备：

| 软件 | 用途 | 建议 |
|---|---|---|
| [Node.js](https://nodejs.org/) | 运行本项目的开发、检查和构建工具 | 安装 **24 LTS**；会同时安装 npm |
| [Git](https://git-scm.com/downloads) | 获取项目、创建分支和提交改动 | 已有可用版本不必重装；新增安装前确认位置 |
| [Google Chrome](https://www.google.com/chrome/) | 试玩及运行默认浏览器检查 | 本项目的浏览器自动化默认调用 Chrome |
| 代码编辑器或带本地文件访问能力的 AI 开发工具 | 打开项目、编辑文件、运行终端命令 | 使用你熟悉的工具即可；例如 VS Code 配合 AI |

本项目最近使用 Node **24.21.0** / npm **11.17.0** 验证，最低需要 Node **22.12**。优先使用 Node 24 LTS，不需要自行追逐更新版本。

**让 AI 安装环境时，必须先询问安装位置，确认后优先安装到非 C 盘；不能直接采用安装器的 C 盘默认目录。** 先只读检查已有工具、实际路径和可用磁盘，能复用的环境不重复安装，也不擅自卸载或迁移现有软件。

需要提前确认的不只是软件目录，还包括项目和较大的下载/缓存：

| 内容 | 需要与 AI 确认什么 |
|---|---|
| Node.js、Git、编辑器等新增工具 | 使用哪个非 C 盘和具体安装目录；安装器是否支持该位置 |
| 项目源码 | 放在哪个目录；项目依赖 node_modules 随项目放置 |
| npm 下载缓存、确有需要的全局工具 | 当前缓存/全局目录在哪里，是否需要改到已确认的位置 |
| Playwright 下载的 Chromium | 浏览器文件存放在哪个非 C 盘目录，之后运行检查如何使用同一路径 |

例如 `D:\DevTools`、`D:\Projects`、`D:\DevCache` 只是可讨论的目录示例，**不是替你选择 D 盘，也不是自动安装授权**。由你确认本机可用的盘符和目录后再执行。已明确批准的位置可以继续复用，不必每次启动都重新询问。

仅把软件本体装到其他盘，不代表缓存也会随之移动。AI 应在安装前说明实际下载/安装路径；需要设置 npm 缓存、全局目录、PATH 或浏览器环境变量时，先说明影响并获得确认。安装后再检查实际位置是否符合约定。

部分安装器会固定在 C 盘写入组件、配置或临时文件。如果不能完全自定义，AI 必须先说明哪些内容仍会写入 C 盘、是否有其他安装方式，等你决定后再继续；不能承诺完全不写 C 盘，也不能遇到限制后静默改用默认位置。

安装后关闭并重新打开终端，执行：

```powershell
node --version
npm --version
git --version
```

正常情况会分别显示版本号。如果提示「不是内部或外部命令」或「无法识别」，先解决软件安装或 PATH 问题，不要让 AI 为此修改游戏代码。

### 1.2 获取正确的工程版本

让项目负责人提供**仓库地址和可用分支**。可以让 AI 帮你克隆，也可以用编辑器的「克隆仓库」功能。

如果默认分支还没有合并工程化迁移，必须先取得负责人提供的工程分支。本文不会假定某个功能分支已经发布到远端。

打开项目文件夹后，应该能看到这些文件：

```text
pixel-rogue/
├── AGENTS.md
├── README.md
├── package.json
├── package-lock.json
├── index.html
├── src/
└── ...
```

**如果只有一个很长的 index.html，没有 package.json 和 src/，你拿到的是旧 Demo。** 先请负责人或 AI 确认分支，不要在旧 Demo 目录里反复运行 npm 命令，也不要让 AI 重新搭建一个简化版游戏。

通过 ZIP 获取的源码可以用来本地试玩，但 ZIP 通常没有 Git 历史。要长期协作、创建分支和提 PR，优先使用 Git 克隆；已有 ZIP 改动时先让 AI 保留并检查，再决定如何放回仓库。

### 1.3 打开项目终端

推荐在编辑器中「打开文件夹」，选择整个 `pixel-rogue` 文件夹，再打开内置终端，终端类型选择 **PowerShell**。

如果需要手动进入目录，例如你的项目放在 `D:\Projects\pixel-rogue`：

```powershell
cd "D:\Projects\pixel-rogue"
```

上面的路径只是示例，要换成你自己电脑的真实路径。下面所有 npm 命令都在**包含 package.json 的项目根目录**中运行。

复制命令时，只复制代码框内容，不要把别人截图中的 `PS D:\...>` 提示符一起复制进去。

## 2. 第一次运行

### 第一步：安装项目依赖

```powershell
npm ci
```

这会根据 `package-lock.json` 安装项目需要的工具，通常需要联网。它可能花一点时间；正常结束后会回到命令提示符。

`npm ci` 适合首次获取项目，或更新后依赖锁文件发生变化时使用。它会重新安装依赖；**不要在本项目开发服务或生产预览仍运行时执行**，Windows 可能因此出现文件占用错误。日常启动一般不需要重装。

### 第二步：启动开发服务

```powershell
npm run dev
```

终端会显示类似：

```text
Local: http://127.0.0.1:5173/
```

在 Chrome 中打开终端显示的**完整地址**。如果端口被占用，开发服务可能换一个端口，以实际输出为准。

看到游戏开始界面、点击「开始冒险」后可以移动，就说明本地启动成功。

注意以下几点：

- 启动后终端一直停留在服务输出界面是正常的，服务正在运行，并不是卡住。
- 试玩时保持这个终端运行。要执行其他命令，可以再开一个终端。
- 修改代码并保存后，开发页面通常会自动刷新；正在进行的一局可能因此重置。
- 停止服务时，回到对应终端按 **Ctrl+C**，不要只关闭网页。
- 正式工程需要 HTTP 服务，**不能直接双击根目录 index.html 启动**。
- `127.0.0.1` 是你自己的电脑地址，发给朋友后不会变成公开试玩链接。

## 3. 以后每天怎么启动

已经安装过依赖时：

1. 打开项目文件夹和终端。
2. 开发前先让 AI 检查分支、工作区以及是否有需要同步的远端改动。
3. 运行 `npm run dev`，打开终端显示的地址。
4. 做完后按 Ctrl+C 停止服务。

不要每天执行 `npm ci`。如果负责人说更新了依赖，或者 AI 确认 `package-lock.json` 发生了变化，再停止服务并运行它。

**已有未提交改动时，不要直接照抄网上的“强制同步”命令。** 让 AI 先报告哪些文件有改动，再保留改动并处理远端更新。

## 4. 游戏怎么玩

| 按键 | 功能 |
|---|---|
| WASD / 方向键 | 移动 |
| 无需按键 | 自动选择附近敌人并攻击 |
| 空格 | 冲刺，需要先学「疾影步」；支持天赋增加充能 |
| 1 / 2 / 3 | 选择对应升级卡片 |
| C | 打开 / 关闭角色属性面板 |
| P | 暂停 / 继续 |
| M | 静音 / 开声音 |
| R | 死亡后重新开始 |

每波的流程是：**清完敌人配额 → 自动收取经验球 → 选完所有升级 → 查看报告 → 手动开始下一波**。

- 升级时有三张卡，每张卡可以独立刷新一次。
- 升级和伤害报告是底部非暂停面板，计时和冷却仍继续。P 和 C 才会冻结游戏模拟。
- 首领：第 10 / 20 / 30… 波只生成三首巨兽，不刷普通怪或精英。生命 70% / 35% 时切换火、冰、雷三阶段；参照 C 方案太刀的卡通奇幻像素美术，72×56 八姿态和六套技能图集，持续喷火、双重冰环、逐段冰刺与三轮落雷。躲开每轮地面预警，利用冲锋后硬直反打。击败必掉 2 普通宝箱、1 血包及 8 倍精英经验；阶段随从需清空后才收球。详见 [首领机制](docs/boss-three-headed-beast.md)。
- 非首领波的精英固定为岩石巨兽：4/8 波各 1 只，12–19 波每波 2 只，20 波起每波 3 只；第 8 波起随机携带「分裂 / 召唤蝙蝠 / 冰霜新星」词缀。
- 普通 / 特殊怪解锁：史莱姆 1、蝙蝠 3、射手 4、蛮牛 / 角兽 5、战鼓手 7、自爆虫 8、裂胶史莱姆 9、织网蛛 11、掘地虫 13；小史莱姆只由裂胶史莱姆生成。
- 熔炉（置换）入口自 v60 关闭：新职业池没有稀有度分层，实现保留，待重做后开放。
- 切换到后台会自动暂停，返回后需要手动继续。

当前节奏：逻辑画面为 480×270，世界为 1392×1040；非首领波首波配额 20，每波增加 10，上限 150，首领波配额为 1；第 5 波起普通敌人每批生成两只，精英单独生成；初始升级经验为 6，后续阈值为 `ceil(上一次阈值×1.13)`。

桌面优先使用整数倍缩放，小窗口允许缩小和滚动面板。当前没有手机触屏摇杆。

## 5. 借助 AI 协作：推荐工作方式

### 5.1 先理解这几个词

| 名称 | 可以这样理解 |
|---|---|
| 本地工作区 | 你电脑上的项目文件；文件改了不等于已传到 GitHub |
| 分支 branch | 一条独立的修改路线，让不同任务互不干扰 |
| 提交 commit | 在本地记录一批确定的修改 |
| 推送 push | 把本地提交上传到远端仓库 |
| PR（Pull Request） | 请朋友检查并决定是否合并这批修改的申请 |
| 主分支 main | 大家共同使用的稳定版本 |
| 合并 merge | 把通过审核的分支改动纳入目标分支 |
| 构建 build | 把源码转换成可发布的网页文件，输出到 dist/ |

**本项目必须先开功能分支，再开发，最后通过 PR 合并主分支。** 不直接在 main 上写代码或推送修改。当前任务已有合适的功能分支时可以继续用，不必每次对话都新建分支。

### 5.2 一次只交给 AI 一个明确任务

推荐使用这样的流程：

1. 让 AI 先读 `AGENTS.md`、相关代码和当前 Git 状态。
2. 确认正在正确的功能分支；若从主分支开始，先创建任务分支。
3. 写清楚“现在是什么情况”“希望变成什么样”“哪些内容不能改”。
4. 让 AI 实施修改并运行相关现有检查，再实际打开游戏试玩。
5. 让 AI 列出改动文件、检查结果和未验证项。
6. 你确认修改范围后，再明确授权提交、推送和创建 PR。
7. 审阅 PR，通过必要检查和审批后再合并；创建 PR 不等于同意合并。

不要一次说“全面优化一下”。例如，“暂停时冷却仍在减少，修复暂停逻辑”比“把游戏做得更好”更容易验收。

### 5.3 可直接复制：首次接手并运行

将下面这段发送给能访问本地项目和终端的 AI：

```text
请先读取项目根目录的 AGENTS.md 和 README.md，检查当前分支、Git 工作区和 package.json。
先确认这是有 package.json、src/ 的工程化版本；如果还是旧的单 HTML Demo，请明确告诉我，不要重新搭建项目。
先只读检查本机 Node/npm/Git/浏览器是否可复用，以及项目、npm 缓存和浏览器下载的实际位置。
如果需要安装环境、下载浏览器或改变相关全局配置，先告诉我需要安装什么、哪些内容会占用磁盘，并询问我希望使用的非 C 盘盘符与具体目录。
我确认位置之前，不执行安装或浏览器下载，不默认使用 C 盘，也不自行猜测 D/E 盘；可复用我已经明确批准的位置。
安装方式无法避免写入 C 盘时，先说明限制和替代方案，等我决定；不要擅自移动或卸载已有环境。
环境与目录确认后按约定安装，核对实际路径，再使用锁文件安装项目依赖并启动开发服务。
如果存在未提交改动，请保留，不要重置或覆盖。
暂时不要改游戏代码，不要提交、推送、创建 PR 或合并。
最后告诉我实际打开哪个地址、如何停止服务，以及任何尚未解决的问题。
```

如果 AI 只是普通聊天窗口、无法读取你电脑文件或执行命令，它只能提供指导。不要把“建议执行”当作“已经执行”；需要你在终端操作，或换用有本地开发能力的 AI 工具。

### 5.4 可直接复制：开发一项功能

把方括号里的内容换成真实需求再发送：

```text
请先读取 AGENTS.md，检查分支和未提交改动，阅读与任务相关的现有代码。
必须在独立功能分支开发；如果已有当前任务的功能分支就继续使用。

本次需求：[描述要增加或调整的具体功能]
希望的使用过程：[玩家在哪里操作，之后会看到什么]
验收条件：
1. [一个可以实际观察的结果]
2. [另一个可以实际观察的结果]
保持不变：[例如其余天赋效果、伤害数值和像素风格]

请给出简洁计划后直接实施，优先复用现有模块。
运行相关现有检查；涉及界面、输入或场景时实际打开浏览器验证。
遇到影响核心规则且无法确定的歧义，先保留可运行成果并说明。
```

## 6. 检查、测试与生产预览

### 6.1 这些命令分别做什么

| 命令 | 用途 | 正常结果 |
|---|---|---|
| `npm ci` | 根据锁文件安装依赖 | 安装结束，返回命令提示符 |
| `npm run dev` | 日常开发和快速试玩 | 显示本地地址，持续运行 |
| `npm run typecheck` | 检查 TypeScript 类型和未使用声明 | 没有类型错误，命令结束 |
| `npm test` | 执行已有规则、存储和上游对照测试 | 输出通过数量，命令结束 |
| `npm run build` | 先类型检查，再生成正式网页 | 生成 dist/，命令结束 |
| `npm run test:browser` | 在真实浏览器中执行已有流程检查 | 输出各项结果，命令结束 |
| `npm run preview` | 用最新 dist/ 预览将要发布的版本 | 显示本地地址，持续运行 |

最近一次 v8 验证为 **38 项规则测试、6 项浏览器检查通过**，详见迁移记录。后续数量可能变化，以实际执行输出为准。

### 6.2 修改完成后如何检查

让 AI 按任务范围选择现有检查。准备交付游戏逻辑或界面修改时，常用：

```powershell
npm run typecheck
npm test
npm run build
```

任何一步失败，都不能把该项写成“通过”；让 AI 阅读错误、做相关修复后再验证。普通实现任务默认不主动新增测试，遵守 `AGENTS.md` 的测试范围约定。

涉及界面、输入、相机或完整游戏流程时，再运行浏览器检查：

```powershell
npm run test:browser
```

**浏览器检查不会替你构建，必须先成功运行 npm run build。** 它会自动启动 5174 测试服务和 4173 生产预览，这两个端口必须空闲；先在它们各自的终端按 Ctrl+C 停止已有服务。不要同时启动两轮浏览器检查。

默认使用本机 Google Chrome，通常约一分钟，自动化期间没有浏览器窗口也属正常。若没有 Chrome，可以改用 Playwright 下载的 Chromium。**下载前先按「准备环境」约定确认非 C 盘浏览器目录**；下面假设你已经批准使用 `D:\DevCache\ms-playwright`，请换成实际批准的位置：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = 'D:\DevCache\ms-playwright'
npx playwright install chromium
$env:PLAYWRIGHT_CHANNEL = 'chromium'
npm run test:browser
```

这些环境变量设置只影响当前 PowerShell 窗口。以后新开终端运行该 Chromium 时，也要先设置同一个 `PLAYWRIGHT_BROWSERS_PATH` 和 `PLAYWRIGHT_CHANNEL`，无需再次下载。若希望持久化设置，让 AI 先说明影响并获得确认。其他终端使用各自语法；不确定时让 AI 确认，不要混用 Bash 和 PowerShell 命令。

截图位于 `output/playwright/`；失败时的 trace 和上下文位于 `test-results/`。可让 AI 查看这些证据，说明失败发生在安装、启动、操作还是游戏逻辑。

### 6.3 发布前用生产版本再玩一次

开发服务直接使用源码，生产预览使用上一次构建好的 `dist/`。修改源码后，必须重新构建才能在生产预览中看到新效果：

```powershell
npm run build
npm run preview
```

打开终端显示的地址，默认是 `http://127.0.0.1:4173`。

最少亲自试一下：开始游戏、移动与自动攻击、升级选卡、暂停/继续、属性面板、清波后的报告与下一波。修改涉及死亡或重开时，也应试对应流程。

自动检查能减少错误，但构建成功不等于所有玩法都经过了实际试玩。让 AI 清楚写出它验证到哪一步。

## 7. 常见问题

| 现象 | 先做什么 |
|---|---|
| 找不到 package.json / 出现 ENOENT | 确认终端所在目录和分支；根目录应有 package.json、src/ |
| node 或 npm 无法识别 | 重新打开终端，检查 Node 安装与 PATH；不要修改游戏代码解决环境问题 |
| PowerShell 提示 npm.ps1 无法加载或脚本被禁用 | 可将对应命令改为 `npm.cmd`，例如 `npm.cmd ci`；不必先修改系统执行策略 |
| npm ci 出现 EPERM、unlink、文件被占用 | 停止本项目开发服务和生产预览后重试；不随意结束其他项目进程，不递归删除 node_modules |
| 网页打不开 | 确认服务终端还在运行，并使用该终端显示的完整地址 |
| 双击 HTML 后没有正常游戏 | 这是工程版；通过 npm run dev 或生产预览访问 |
| 修改后生产预览没有变化 | 停止预览、重新构建、再启动预览，必要时刷新页面 |
| test:browser 提示端口已使用 | 检查 5174 / 4173 是否有本项目之前启动的服务，回到对应终端停止它；不盲目换端口 |
| Playwright 提示找不到浏览器 | 检查系统 Chrome，或按上文安装 Chromium 并设置环境变量 |
| 出现 npm WARN 或大包体积警告 | 把完整警告交给 AI 判断；警告不自动等于失败，也不要为了消除它盲目升级依赖 |
| 浏览器检查失败 | 看具体失败项、截图和报错；不能通过删检查或跳过真实功能来“修好” |
| 切换地址后战绩不见了 | 浏览器本地数据按地址隔离，先确认原浏览器和原地址；不要直接清空数据 |
| Git 报冲突或不能更新分支 | 暂停写入，先让 AI 列出冲突及本地改动、给出保留方案，不使用强制覆盖命令 |

需要求助时，提供：执行的命令、相关完整错误、当前分支、最后一次成功的操作。避免只说“坏了”；也不要公开整个包含敏感信息的日志或配置。

## 8. 战绩和数据保存在什么地方

战绩存在当前浏览器的 **localStorage** 中，使用键 `pixelrogue_records`，最多保留最近 50 场，与旧版记录兼容。

- 它不是项目目录里的文件，也不是 GitHub 上的数据。
- 更换浏览器、设备、域名或端口，会进入不同的数据空间。
- 清除网站数据可能删除战绩；无痕窗口的数据通常不会长期保留。
- 旧版 file://、本地开发地址和发布后的 HTTPS 地址之间不会自动搬迁战绩。
- 存储被拒绝、容量不足或格式损坏时，游戏可以继续；结算会提示保存失败，未知或损坏数据不会被覆盖。
- **目前只保存战绩，不支持退出后继续同一局，也没有云同步。**

## 10. 发布到静态托管

本项目可以纯静态发布，不需要 Node.js 后端、数据库、账号系统或 Worker。**npm run dev / preview 都只是本地服务，不等于已发布。**

提供两种方式：**GitHub Pages（本仓库已配置自动部署，推荐）** 与 Cloudflare Pages。

发布前由负责人确认本次版本和目标仓库。下面是部署说明，实际连接账号、创建项目或发布应由获得授权的人执行。

### 方式 A：连接 Git 仓库自动构建

在 Cloudflare 中进入 Pages 创建入口，连接确认过的 Git 仓库，再填写：

| 设置 | 填什么 |
|---|---|
| 框架预设 | 没有适用预设时选择 None / 无 |
| 根目录 | 仓库根目录；通常留空，不填 src |
| 生产分支 | 经团队确认的主分支，通常为 main |
| Node 环境 | 24，可按平台设置 `NODE_VERSION=24` |
| 构建命令 | `npm run build` |
| 构建输出目录 | `dist` |

依赖使用锁文件安装（`npm ci`）；若平台已自动安装依赖，保留构建日志并确认安装与构建均成功。需要显式配置安装和构建时，可按平台的构建设置处理，不改游戏源码迁就错误配置。

首次发布后打开平台提供的 HTTPS 地址，测试资源加载、开始游戏和一波完整流程。后续按分支和 PR 流程更新源码，平台才会按配置构建发布。不要把功能分支直接设为生产分支来绕过审核。

### 方式 B：手动上传已构建文件

先在本机检查并构建：

```powershell
npm ci
npm test
npm run build
```

再用 `npm run preview` 试玩，确认后在 Pages 的直接上传流程中上传 **dist 里的完整内容**。站点根目录应直接包含构建后的 `index.html` 和 `assets/`。

不要只上传一个 HTML，也不要把 `src/`、`node_modules/` 或整个开发仓库当作发布文件。`dist/` 是生成目录，通常不提交 Git；别人从仓库获取源码后需要自行构建。

### 方式 C：GitHub Pages（本仓库已配置自动部署）

仓库包含 `.github/workflows/deploy.yml`：**每次合并到 `main` 会自动构建并发布**，无需手动操作。

- 在线地址：<https://reopen64534042-sudo.github.io/pixel-rogue/>
- 触发条件：push 到 `main`，或在 Actions 页面手动运行 `Deploy to GitHub Pages`
- 构建流程：`npm ci` → `npm run build`（内含 `tsc --noEmit` 类型检查）→ 上传 `dist`
- 首次启用：仓库 Settings → Pages → Source 选择 **GitHub Actions**

两个容易踩的坑：

1. **`dist/` 是构建产物、被 `.gitignore` 忽略，`git pull` 不会更新它**。想在本机看到最新版本，请用 `npm run dev`（见[第一次运行](#2-第一次运行)），不要直接打开 `dist/` 里的旧文件。
2. `dist/index.html` **不能双击打开**——Vite 产出的是 ES module，浏览器用 `file://` 加载会被 CORS 拦截，必须通过 HTTP 访问（`npm run dev` 或 `npm run preview`）。

Vite 使用 `base: './'`，资源相对部署位置解析，支持静态子目录。字体已自托管，运行不依赖 Google Fonts/CDN。发布时保留 `dist/PHASER-LICENSE.md`、`dist/THIRD_PARTY_NOTICES.md` 与字体的 `assets/fonts/OFL.txt`。

## 11. 给继续维护项目的人

具体版本与依赖以 `package.json` / 锁文件为准。当前主要技术为 TypeScript 6.0.3、Vite 8.3.5、Phaser 4.2.1、Vitest 5.0.5、Playwright 1.64.1。

`GameCore` 持有每局状态和规则命令，不依赖 DOM 或 Phaser；UI 通过命令操作游戏，Scene 管理输入、相机和唯一更新循环。渲染使用复用的 Phaser Graphics/Image/Text，不把旧 Canvas 每帧上传成贴图；Canvas 用于生成像素纹理与 Phaser 内部文字栅格化。

本项目仍是试玩版。完整 Phaser 包带来约 375 KB gzip 的 JS 下载量，构建保留体积警告；尚未完成多小时长局、Firefox/Safari、各类显卡与低性能设备的全面验收。已有自动检查和本机试玩证据不等于覆盖所有环境。

继续开发时，优先保留完整可玩循环，按实际证据修复问题。不要随意删除机制、改变平衡或引入大型新框架；更多规则以 [AGENTS.md](AGENTS.md) 为准。

居合回旋斩素材已提供场景预载、PixelPainter 绘制接口与标准 Phaser 图集，接入方式和资源规格见 [居合回旋斩 VFX 素材](docs/iai-spin-slash-vfx.md)。

大剑主动跃击与第三段坠击已包含默认预载、0.24 秒起手、落点预警、坠落状态和正式落地素材，合入后按正常战斗流程直接使用。触发方式、完整接线、资源路径与标准 Phaser 示例见 [大剑跃击与第三段坠击接入说明](docs/greatsword-leap-vfx.md)。

大剑剑气 / 裂地 / 冲刺斩素材已默认预载；三段斩的 130° 冲刺扇斩直接使用新薄刃刀光。另提供可直接调用的 `drawGreatswordWave` / `drawGreatswordDashSlash` 表现接口，移动剑气与四方裂地由玩法分支传入实际波面状态接入。接口参数、已完成接线与移动波面示例见 [素材与直接接入说明](docs/greatsword-vfx-prompts.md#直接接入接口v133)。
