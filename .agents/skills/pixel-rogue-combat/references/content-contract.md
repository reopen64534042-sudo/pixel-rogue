# 战斗内容契约

新增职业、武器、怪物或新结算能力时使用。记录在该内容已有设计文档或 docs/migration.md，不必新建一份副本；单系数修改只填写变化项与消费者。

本文是工作模板，不是运行时注册表；表中的示例不授权添加数值、机制或新属性。先以当前源码填已知项，再标注需用户决定的实质设计。

## 0. 新武器 / 新怪物的必填声明

以下内容必须出现在该内容的设计或实现记录中，可引用已确认的公共规则；不能只写“沿用默认”而不指明沿用哪一条规则。

| 对象 | 必须明确 |
|---|---|
| 武器主攻击 | 伤害属性 type、攻击形式 form、raw 公式、暴击与增伤、防御策略；例如“雷电 / melee / 吃雷抗”是三个独立决定 |
| 武器派生伤害 | 爆炸、附伤、地面、反击等逐项列 type/form、继承和触发权限；混合伤害逐分量填写 §2 |
| 怪物基础防守 | 基础护甲 defense、通用减伤 tough，以及各项的成长或明确复用的成长规则 |
| 怪物元素抗性 | 按 DAMAGE_TYPES 中 mitigation=resistance 的类型逐项列出；当前为火、冰、雷。正值为抗性，负值为弱点，0 表示明确中性 |
| 非抗性防御 | 当前物理和引力使用护甲；真实绕过 armor/resistance/tough。填写对应策略，不编造 resistances.gravity 等未被消费的防御 |
| 怪物控制规则 | 减速、冻结、眩晕、定身、牵引/击退的适用、免疫、精英/Boss修正或明确引用的规则；不从元素抗性推导 |
| 怪物进攻 | 接触、弹丸、技能、地面效果各自的伤害属性与形式；“会放火”不能代替火抗数值 |

设计声明中的 0 不要求在配置、实体或快照里新增本来缺省的键；保持既有中性缺省和可选字段语义。不自行增加伤害类型、抗性或改动旧内容的平衡。

## 1. 归属与属性来源

| 项目 | 本次内容填写 |
|---|---|
| 名称、稳定 ID、职业/武器/流派或怪物类型 | |
| 范围：新增能力 / 接线修复 / 只改数值 / 只做设计 | |
| 基础属性拥有者 | 文件、函数、字段 |
| 人物成长与武器成长 | 各自来源；无该成长则说明 |
| 属性点 / 天赋 / 永久来源 | stat、stage、value 单位、sourceId、同次投影入口 |
| 键控属性 | family + key、来源适配/键所有权；不支持则列出需补链路 |
| 现有键控接线 | 属性选择用 stat+key → attributeStatSources；独立来源用 PlayerKeyedStatSource，声明稳定 ownedKeys，经 applyTalentStatProjection 同次投影；失效以空 modifiers 清旧值 |
| 投影、快照、最终消费者 | 函数与字段；没有投影消费即未接通 |
| 上限/下限 | 配置位置、执行位置；区分候选过滤与所有来源硬顶 |
| 重算后行为 | 同样来源得到同样属性，当前资源/计时如何保留 |

数据单位必须清楚：护甲为点数，抗性/增伤为小数比例，final 为倍率，tick 为秒或明确次数。不要以“百分比”一词混用数种阶段。

## 2. 每条攻击 / 每个分量一行

| 攻击或分量 | raw 公式/函数 | type | form | hit/dot + 精度 | 取样时机/快照 | 增伤继承/暴击 | src/统计 |
|---|---|---|---|---|---|---|---|
| 主攻击 | | | | | | | |
| 附伤 / 爆炸 / 子弹 / 地面 / 反击 / 召唤等实际存在的派生 | | | | | | | |

删去不涉及的示例行或写不适用。混合伤害分别列物理/元素/真实/生命压缩等分量，并说明同次应用方式，不把一个含糊“总伤害”递归送入多个命中入口。

逐行回答：

- raw 已包含哪些攻击/武器/条件倍率；派生继承 raw、结算伤害还是实际 HP 损失，是否会再次经过同一乘区。
- global / type / form / skill 四区是否继承；有 skillId 时链路是否真实可达。
- 暴击在哪里掷骰、共享多久；hit 是否连续积分；dot 必须不暴击且保留浮点。
- 攻击快照何时取；防守方是否命中时读取；范围攻击 origin 是玩家/弹着点/爆炸中心哪一个。
- 若使用已有帮助函数，其默认 type/form/触发权限是否符合本次语义。
- 武器/派生、怪物/Boss、弹丸/接触/地面在 data/attackProfiles.ts 登记 type/form/skillId；时变属性用 withDamageType 显式覆盖。普通攻击包装已透传 skillId，分量是否继承仍由本表明确。无命中触发的 DoT 使用 applyEnemyDotDamage，不能重复扣血、加最终倍率或再次记账。

## 3. 防守、状态与触发权限

| 项目 | 必须明确的决定及落点 |
|---|---|
| 受击防御 | 基础 defense；fire/frost/lightning 抗性或弱点；tough；不配置时明确中性 |
| 策略 | 使用 armor / resistance / none；gravity 当前吃护甲，不能仅配 gravity 抗性 |
| 破甲/穿透/方向 | 是否支持、如何合成、入射点来自哪里 |
| 最终修正 | 难度 damageTakenMul、Boss 无敌/易伤各应用几次 |
| 盾和无敌 | 次数盾/数值盾、吸收时点、hurtCd/dash 门禁、免死 |
| 异常/控制 | 施加/免疫/持续/叠层/刷新/精英/Boss/递减归属；不从元素抗性推断 |
| 命中特效/连锁/再触发 | 主/派生是否允许；递归停止条件 |
| 吸血/治疗 | 基数、实际 HP 损失、共享预算、派生权限 |
| 武器 XP/掉落 | 每击/每轮/每目标/时间窗；尸体与同次多分量不重复计入 |

新怪物的进攻属性与防守抗性分开填写：“造成火焰伤害”不代表“自动有火焰抗性”。

## 5. 完成时留痕

简短列出：

- 实际闭合的来源与消费者（文件/函数），以及复用的既有入口。
- 与旧行为的差异、过期断言或相邻缺口。
- 仍待决定/未实现项；有未闭合必要链路时不得宣称功能完整。
- 本次 typecheck / build / diff 或文档技能校验结果；遵守当前“不主动补测试”的政策。
- 现有内容复用位置与静态覆盖结果：node scripts/audit-combat-contracts.mjs；源代码变化后用 --write 刷新清单，新隐藏子体等未入图鉴时说明原因。
