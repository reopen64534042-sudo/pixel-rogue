# Pixel Rogue 战斗内容接入

用于本仓库战斗内容的设计、实现与接线核对。先服从当前任务范围和 AGENTS.md；不得把整理流程理解为批准重平衡、全面重构、恢复退役机制或 Git 写操作。

## 开始时

1. 确认仓库根目录和工作区；代码路径以仓库根解析，Markdown 链接相对所在文件。保留他人修改，在本任务分支或独立 worktree 工作。
2. 首次用于当前任务时读 [当前系统总览](../../../docs/combat-system-current.md)，再从 [现有覆盖清单](../../../docs/combat-coverage.md) 找到相近攻击/怪物；按 [Agent 指南](../../../docs/combat-numerics-agent-guide.md) §2 和任务对应 §3 小节打开拥有者/消费者。
3. 文档快照不是当前行为的证明。核对对应源码；若不一致，先记录实际路径及差异。不要沿用旧 Foundation 文档中未启用负抗性、四属性或 StatModel 未运行时接入等过期描述。

## 先明确能力，再接线

用 [内容契约](references/content-contract.md) 明确新增内容；小改动只记录变化项。已有设计文档可直接承载，不强制新建文件。未用的字段写明不适用及原因；不能让默认 physical / other 代替设计决策。

**新增武器必填**：主攻击与每个实际派生分量分别明确伤害属性 type、攻击形式 form、对应防御策略和适用增伤；混合伤害分开声明。武器名、职业、外观、特效颜色和控制效果都不能代替伤害属性。

**新增怪物必填**：明确基础护甲 defense、按当前注册表所有 resistance 策略类型逐项列出的抗性/弱点、通用减伤 tough；没有某项抗性也要明确为 0 或引用已确认的中性规则。armor / none 策略不虚构独立抗性键，例如引力当前由护甲防御。另行声明控制免疫/递减，以及怪物各攻击的 type/form；进攻属性不自动决定防守抗性。

这里要求设计声明完整，不要求运行时把全部中性字段写成 0；保持既有可选字段形状。已批准设计或明确复用规则可以直接引用；关键属性仍未确定时列为待决定，不自行补出平衡数值或宣称完成。

必须能回答：

- 基础属性、人物等级、武器等级、属性点、天赋分别由谁提供；是否经过同一次来源解析与实体投影。
- 主伤和每个派生分量的 raw 公式、type、form、kind、精度、快照、增伤继承与统计来源。
- 受到哪种护甲/抗性/tough/最终倍率影响；盾、方向、无敌、免死、控制规则如何处理。
- 暴击、命中特效、吸血、武器 XP、连锁/再触发是否允许，按每击/每目标/每轮/时间窗共享。
- 新内容如何进入卡池/刷新池，如何更新、死亡、换波、重开及展示。

设计请求只产出明确的方案与未定项；实现请求继续落实获授权的代码。平衡数值缺失且会影响正确性时询问用户，同时推进不依赖该决定的工作。

## 实现时

沿“来源 → 解析 → 实体 → raw/快照 → 请求 → 防御/HP应用 → 死亡/统计/显示/重置”逐项闭合，用实际函数名记录复用/修改位置。

- 新伤害系数与纯公式放 combatBalance / DamageMath；系统负责选目标、时序和状态，DamageSystem 只做纯计算。
- 玩家永久来源统一合成；检查 f / Modifier / upCounts 消费方式，避免重复加成或重算抹除。键控属性选择使用 stat + key，经 attributeStatSources 与 PlayerCombatSources 投影；独立映射来源声明稳定 ownedKeys，失效时传空 modifiers，不能只省略来源留下旧值。
- 职业/武器/来源不等于伤害类型；type 与 form 独立。新属性类型须连防守映射和显示消费者一起核对。
- 技能增伤使用 HitOptions / PlayerHitOptions.skillId，现已透传；src 不会自动成为技能键。分量明确 inheritBonuses 和可选独立 skillId，避免把同一增伤重复烘焙进 raw。
- 现有武器主/派生、怪物/Boss、弹丸/接触/地面在 data/attackProfiles.ts 声明独立 type、form、skillId；新增攻击也要登记，不能只沿用受击包装的缺省。时变元素/离子/真伤用 withDamageType 显式覆盖 type，不改变 form 或技能身份。
- 普通命中与连续武器复用 hurtEnemy；无命中触发的 DoT 复用 EnemyDamageApplication.applyEnemyDotDamage。最终倍率与 HP 由公共应用层处理，保留两条路径的浮点/取整政策和原调用侧死亡时序。
- 新怪物还要处理主题权重、行为、攻击上下文、精英/子体、死亡/图鉴。只填 ETYPES.wt 不会进入普通刷新池。
- 保留快照/RNG/取整政策；continuous hit 与 dot 分开。DoT 副作用和多分量继承逐项声明，避免每帧保底1、重复增伤、递归触发和重复掉落。
- 保持现有合法特例。只修本任务必需的接线，不顺手迁移全部旧机制；记录发现的相邻缺口。

## 交付前

1. 用契约逐项对照实际来源和消费者，写出已复用/已实现/不适用/待决定项。不要用一次大范围搜索替代闭合检查。
2. 战斗代码改动执行 node scripts/audit-combat-contracts.mjs，检查受击入口显式字段、HP 扣除位置和怪物/图鉴引用；用 --write 更新 docs/combat-coverage.md。然后按项目约定执行 typecheck、build、diff。静态核对不执行模拟，不代替运行时验收；仅文档/skill 改动校验结构、路径、描述与 diff，skill 修改运行 quick_validate（可用时）。
3. 默认不新增/扩展测试，不运行 Vitest / Playwright。过期断言留痕，遵守当前 AGENTS 的集中验证安排。
4. 更新相关说明与迁移记录；生产功能按项目规则维护双份更新日志。清楚区分实现、编译证据、受控检查、自然玩法及未验证项。
