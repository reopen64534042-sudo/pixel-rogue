# 任务说明：残局敌人方向指示器

> 状态：**待实现**（本文只给方案，不含代码）
> 关联：#180 战士平衡、`docs/migration.md` D-114
> 用途：交给其他实现者按本文落地，避免重复踩已探明的坑

## 一、为什么需要这个

战士平衡批（v109–v110）的实测结论：

| 手段 | 第 4 波清场耗时 |
|---|---|
| 改前（太刀 9/34、暴伤 2.0、移速 60） | 超时（>120s） |
| 太刀 12/42 + 冲刺特化 + 残局收拢阈值 5 | 92–106s |
| 再加：残局收拢阈值 5 → 12 | **85.8s** |

清场末尾剩 6–12 只射击怪时，它们分散在 **1392×1040** 的世界里，而相机视野只有
**480×270**。玩家几乎全程在跑图找怪。**这段耗时与 DPS 无关**——实测把伤害提到 15、
射程提到 60、移速提到 80 都无法压缩它。

因此再往下压单波时长，方向不是战斗数值，而是**告诉玩家怪在哪**。

## 二、需求

> 用户原话：「在剩下最后 5 只怪的时候，依次给距离当前角色最近的怪的方向标记方向，
> 记号要足够简洁醒目」

解读（实现前请与需求方确认，见「六、待决策点」）：

- 触发条件：场上存活敌人 **1 ≤ n ≤ 5**
- 每次**只标一只**：当前距离玩家最近的那只；它死后自动切到下一只（"依次"）
- 标记分两种形态：敌人在视野内 / 在视野外

## 三、落点与坐标系

唯一改动文件：`src/game/rendering/draw.ts`，函数
`export function draw(this: GameCore, ctx: PixelPainter)`（约第 103 行）。

**这个函数内部有两套坐标系，必须区分：**

| 范围 | 坐标系 | 说明 |
|---|---|---|
| 函数开头 ~ `ctx.screen()` 调用处（约 1160 行） | **世界坐标** | 相机变换生效，`cx = this.cam.x` / `cy = this.cam.y` 是相机左上角 |
| `ctx.screen()` 之后 | **屏幕逻辑坐标** | `0..VIEW.w`(480) × `0..VIEW.h`(270)，所有 HUD 都画在这里 |

指示器要钉在屏幕边缘，**必须画在 `ctx.screen()` 之后**。若画在世界坐标段，标记会
随相机滚动，不固定在屏幕上。

`VIEW` 常量在 draw.ts 中已导入，无需新增 import。

## 四、算法

```
存活 = this.enemies.filter(e => !e.dead)
若 存活.length == 0 或 > 5 → 跳过

最近 = 存活中按 (e.x - player.x)² + (e.y - player.y)² 取最小
sx = 最近.x - cx          // 转屏幕坐标
sy = 最近.y - cy
pad = 9                   // 边缘留白

若 sx ∈ (pad, VIEW.w - pad) 且 sy ∈ (pad, VIEW.h - pad)：
    // 情况 A：视野内 → 头顶标记
    在 (sx, sy - 最近.r - 9) 画 4×4 像素块
否则：
    // 情况 B：视野外 → 边缘箭头
    ang = atan2(sy - VIEW.h/2, sx - VIEW.w/2)
    c = cos(ang), s = sin(ang)
    hw = VIEW.w/2 - pad, hh = VIEW.h/2 - pad
    t  = min( |hw/c|  (c≈0 时跳过),  |hh/s|  (s≈0 时跳过) )
    px = VIEW.w/2 + c*t
    py = VIEW.h/2 + s*t
    在 (px, py) 画 4×4 亮块作为箭尖
    再沿 (-c, -s) 方向错开 3px、6px 各画 2×2 小点作为尾迹
```

尾迹的作用是把「一个方块」变成「一只朝外的箭头」，成本只有两个 `fillRect`。

## 五、项目硬约束（不遵守会踩坑）

### ① `PixelPainter` 没有 `fill()`

可用原语：`fillRect`、`beginPath` + `moveTo` + `lineTo` + `stroke()`。
`stroke()` 的线宽**固定 1px**（在 `beginPath` 内部写死 `.lineStyle(1, ...)`），画不出粗箭头。

→ **实心图形只能用 `fillRect` 拼像素块**。这也符合像素美术风格。

### ② 表现层禁止 `Math.random`

会打乱 parity 的确定性随机序列。闪烁必须用确定性相位：

```ts
const pulse = 0.65 + 0.35 * Math.sin(this.time * 7);
```

### ③ 建议只在 `this.wavePhase === "fight"` 时显示

否则波次结算界面（`rest`）上会残留一个指向空气的箭头。
**这一条未经验证**，实现者请目测确认。

### ④ 敌人字段

`this.enemies` 中每项是 `Enemy`，本任务只需要 `x`、`y`、`r`（半径）、`dead`。
已死亡的敌人仍留在数组里（`dead = true`），**必须过滤**。

## 六、待决策点

实现前需确认（本文档不预设答案）：

1. **「依次」的语义**：只标最近的一只（现方案），还是同时标出全部 5 只？
   本文按「只标最近的一只」设计。
2. 是否显示**距离数值**（如「87px」）？
3. 是否区分**精英**（换色 / 更大号）？
4. `rest` 阶段是否也要显示？
5. 标记是否需要在敌人进入视野后**短暂淡出**，避免与敌人本体视觉打架？

## 七、视觉参数建议

参考实现（未经充分验证，仅作起点）：

| 参数 | 值 |
|---|---|
| 颜色 | `#ffd24a`（金黄，与 HUD 强调色一致） |
| 箭尖 | 4×4 `fillRect` |
| 尾迹 | 2 个 2×2，间隔 3px，alpha × 0.55 |

## 八、验收方法（含已踩过的坑）

浏览器受控夹具（Playwright / devtools），必须保证波次停留在 `fight`：

```js
const g = window.__PIXEL_ROGUE__.core;

// ❌ 错误：g.quota = 0
//    波次立刻判定清场 → 敌人被清空、界面转 rest，截出来是空场景

// ✅ 正确：
g.wavePhase = "fight";
g.quota = 20;
g.spawnedThisWave = 20;        // 假装已刷满，阻止继续生成
g.enemies.forEach((e) => (e.dead = true));
g.enemies.length = 0;

for (const [dx, dy] of offsets) {
  g.spawnEnemy("slime");
  const e = g.enemies.at(-1);
  e.x = Math.max(20, Math.min(1372, g.player.x + dx));  // 别越出世界 1392×1040
  e.y = Math.max(20, Math.min(1020, g.player.y + dy));
  e.hp = e.maxhp = 1e6;        // 防止被打死
}
```

等待 **≥400ms** 再截图，否则渲染未跟上。

三个必测场景：

| 场景 | 构造 | 期望 |
|---|---|---|
| 全部在视野外 | 3–5 只，偏移 ≥300px | 屏幕边缘出现箭头，方向与敌人实际方位一致 |
| 最近的在视野内 | 1 只，偏移约 60px | 敌人头顶出现标记，不遮挡本体 |
| 超过阈值 | 6 只 | **不出现任何标记** |

## 九、与已交付改动的关系

本任务**不涉及**任何数值改动。已合并的 v109 / v110 改动（太刀 12/42、冲刺特化、
暴伤 1.5、连斩限三连、残局收拢阈值 12）保持不变。

残局收拢（`EnemySystem.ts` 中 `fewLeft` 判断）与本指示器**互补**：
收拢让怪主动靠近，指示器让玩家知道怪在哪。两者叠加才是完整的「残局体验修复」。
