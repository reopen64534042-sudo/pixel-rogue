> 核对基线：2026-11-01，`upstream/main@6c269e2`（v172）及本分支 v173 整理。公共应用层、技能增伤接线和玩家映射来源已落地；基础数值、抗性、伤害系数和既有分类保持原值。后续实现以对应源码为准；原 Combat Foundation v1 保留为设计历史。
>
> 开发入口：[Agent 接入指南](combat-numerics-agent-guide.md) · [新增内容 skill](../.agents/skills/pixel-rogue-combat/SKILL.md) · [怪物数值表](monster-numerics.md)

> 全量现有路径见 [源码生成的覆盖清单](combat-coverage.md)：75 个攻击声明、40 个实际受击调用点、17 份怪物配置/18 条图鉴。静态覆盖完整与运行时验收是不同结论。

## 1. 先区分六个概念

| 概念 | 回答什么问题 | 当前例子 |
|---|---|---|
| 职业 / 武器 / 流派 | 谁在使用哪套玩法 | 射手 + 激光；法师 + 领域；战士 + 大剑 |
| 伤害属性 `type` | 这部分伤害用什么防御公式 | 物理、引力、火焰、冰霜、雷电、真实 |
| 攻击形式 `form` | 哪种形式增伤适用 | `melee / ranged / other`，由攻击明确声明 |
| 统计来源 `src` | 报告把伤害记在哪里 | `laser / missileMain / cast / domain` |
| 结算性质 / 精度 | 是否持续伤害，如何取整 | `hit / dot`；整数命中 / 浮点结算 |
| 状态与控制 | 是否燃烧、冻结、眩晕、牵引 | 各系统显式施加，伤害属性不自动附送 |

因此，“激光”是武器/统计来源，当前实际造成物理远程伤害；“引力”是伤害属性，当前使用护甲策略；“冰霜抗性”只减少冰伤，不自动缩短冻结。

`skillId` 是另一个精确的技能增伤键，不能用 `src` 代替。当前 hurtEnemy / damagePlayer、附伤分量与公共 DoT 入口均已支持传递；攻击要明确使用同一个键，不能只配置映射。

## 2. 从属性到扣血的实际分层

1. **属性来源**：职业基础、人物等级成长、属性点、天赋、怪物配置和波次/难度。
2. **属性解析与投影**：StatModel / StatKeyedMap 求值；来源适配器把结果写回 Player / Enemy。
3. **攻击生成**：武器/技能形成原始伤害，决定攻击方快照时机、属性、形式、暴击和触发权限。
4. **受击编排**：CombatSystem 处理无敌、盾、条件修正；无普通命中触发的 DoT 委托 EnemyDamageApplication 的公共入口。
5. **数值计算**：DamageSystem 处理增伤、暴击、护甲/抗性、通用减伤和精度。
6. **应用结果**：EnemyDamageApplication 复用最终承伤与 HP 写入；命中保留原副作用时点，公共 DoT 统一同步 Boss 与记账，死亡/掉落仍在各自原调用侧。

StatModel **已经用于运行时**的玩家投影和敌人生成；StatSheets 仍是只读 shadow 工具。不能因为文件历史注释写着 S4-A / S4-B，就认为两者都没有运行时消费者。

### 属性怎么合成

```text
有效属性 = (base 按顺序加上各项 flat)
         × (1 + sum(percent))
         × 各项 final（按顺序连乘）
```

`flat +0.04` 可以表达“全局增伤 +4 个百分点”；再由伤害公式乘 `1 + 0.04`。`final=1.2` 表示乘 1.2，并非 +1.2。不能把所有百分号都写成 `percent`，也不能在天赋 f 和来源投影里重复加同一项。

### 伤害怎么算

```text
计算器伤害 = rawAmount
           × (1 + 全局增伤)
           × (1 + 对应伤害属性增伤)
           × (1 + 对应攻击形式增伤)
           × (1 + 对应技能增伤；请求有 skillId 才读取)
           × 暴击倍率
           × 属性防御系数
           × 通用减伤系数
```

原始伤害已经包含攻击力、技能系数以及该路径明确计入的条件倍率；计算器不会再乘一次快照中的 attack。武器专属倍率应明确算在原始伤害还是某个增伤区，不能同时进入两处。

## 3. 六种伤害属性与防御

注册表：`src/game/data/damageTypes.ts`；参数：`data/combatBalance.ts`；实现：`core/DamageSystem.ts`。

| 属性 | 策略 | 使用的防御 | 是否受 tough 通用减伤 |
|---|---|---|---|
| physical 物理 | armor | 护甲 defense | 是 |
| gravity 引力 | armor | 护甲 defense；不是独立“引力抗性” | 是 |
| fire 火焰 | resistance | resistances.fire | 是 |
| frost 冰霜 | resistance | resistances.frost | 是 |
| lightning 雷电 | resistance | resistances.lightning | 是 |
| true 真实 | none | 绕过上述三种防御 | 否 |

| 防御 | 实际公式 / 含义 | 不能混用的含义 |
|---|---|---|
| 护甲 | 承伤系数 `50 / (50 + max(0, defense))` | 不是直接减固定伤害；不挡三系元素 |
| 元素抗性 | `1 - clamp(res, -0.5, 0.75)` | `0.3` 是 30%；`-0.2` 是对应伤害增加 20% |
| tough 通用减伤 | `1 - clamp(tough, 0, 0.6)`，与属性防御相乘 | 不是控制抗性，也不是射手动态难度 DR |
| 护甲穿透 / 破甲 | 敌方快照中的护甲变为 `DEF × (1-破甲比例) × (1-穿透比例)` | 不降低元素抗性；穿透由调用路径提供 |
| 难度承伤倍率 | `Enemy.damageTakenMul`，计算器之外最终乘算 | 真实、百分比生命伤害和 DoT 仍受影响 |
| Boss 状态倍率 | 转阶段无敌；硬直时由 bossDamageTakenMultiplier 提供易伤 | 不应伪装成某一种抗性 |

例如原始伤害 100、无增伤/暴击、目标 DEF=50、火抗=25%、tough=20%：

| 属性 | 属性防御后 | 再乘通用减伤 |
|---|---:|---:|
| 物理 / 引力 | 50 | 40 |
| 火焰 | 75 | 60 |
| 真实 | 100 | 100 |

若额外存在最终承伤倍率 0.8，上表再变为 32 / 48 / 80。此例是公式演算，不是游戏平衡结论；真实伤害也没有绕过最后一层。

### 哪些防御有玩家可获得的来源

当前玩家属性选择有护甲和闪避；战士还有基础护甲及人物等级护甲成长。常规属性候选没有元素抗性、tough、类型/形式/技能增伤条目。Player 和快照“支持字段”，不等于普通玩家“能获得该属性”。

怪物的护甲/抗性直接由 ETYPES / boss 配置，经 EnemyStatSources 生成；负抗性已经用于多种怪物。当前为 17 份配置、18 条图鉴，岩石兽与岩石巨兽精英复用 brute 基础配置。完整基础值与成长见 [monster-numerics.md](monster-numerics.md)，逐配置抗性与图鉴引用见 [覆盖清单](combat-coverage.md)，不要在 skill 再维护数值副本。

玩家现在也有统一的键控来源链路：属性候选/选择携带 stat+key，由 attributeStatSources 拆成标量和映射来源，在学习/重算时交给 PlayerCombatSources。来源声明稳定 ownedKeys，失效时以空 modifiers 清旧值；同一键多个来源合并后解析，不与上次投影累加。本轮只提供接线能力，没有添加新的抗性卡或类型增伤数值。

## 4. 盾、无敌和控制独立处理

**玩家受击**的主顺序在 `CombatSystem.damagePlayer`：

武器特定受伤修正 → 无敌/虚影等早退 → 闪避 → 赌命增伤 → 临时次数盾 → 普通次数盾 → 元素使数值盾 → 领域数值盾 → 施法打断/相位等机制 → DamageSystem → 扣血与死亡保护。

- 次数盾挡整次命中；数值盾按值吸收，当前在护甲/抗性计算前扣除原始伤害。不要擅自把盾移动到防御之后。
- 真实伤害只绕过 DamageSystem 的 armor/resistance/tough，仍可能被无敌、闪避、盾或免死挡住。
- `hurtCd / dashT` 等门禁有一部分在攻击调用方；不能以为直接调用 damagePlayer 就具备完整命中门禁。
- 冻结、眩晕、定身、牵引、击退与元素抗性相互独立。当前不存在统一的“控制抗性属性”自动覆盖各系统；Boss、精英、领域递减等规则由各自系统判定。
- 领域的共享控制递减是领域路径自己的状态，不应描述为全游戏所有硬控统一递减。

## 5. 七种武器 / 流派现在如何接入

| 玩法 | 主要伤害属性 / 形式 | 入口与需要保留的边界 |
|---|---|---|
| 强化弹射手 | 物理 / ranged；指定真伤弹走 true | AttackSystem + ProjectileSystem；发射快照、穿透/弹射衰减、强化弹专属触发 |
| 激光射手 | 物理 / ranged | LaserSystem；浮点连续命中仍是 hit；同目标复用暴击/命中特效窗口，附属束关闭重复触发，武器共享吸血预算 |
| 导弹射手 | 主爆炸物理或离子雷电 / ranged；余烬火焰 dot / ranged；部分派生 true | MissileSystem + MissileCombat；齐射快照、主弹暴击复用、派生隔离、余烬积分和每轮 XP 上限 |
| 元素使（mage / arcane） | 火/冰/雷 / other；反应也按明确元素结算 | MageSystem + ElementSystem；直伤 hurtEnemy，元素 DoT 独立浮点应用；配对元素额外增伤有专属逻辑 |
| 领域师（mage / domain） | 引力 / other，形成爆发另含 true 及当前生命压缩 | DomainSystem；主伤与 components 同次应用，分量明确是否继承增伤；场/洞快照、领域值 M、穿透与治疗另有边界 |
| 太刀战士 | 核心挥砍/居合物理 / melee | MeleeSystem + WarriorSystem；战士近战基础穿甲，命中列表与连段/冲刺状态 |
| 大剑战士 | 核心挥砍/三段斩物理 / melee | 同一近战框架 + 大剑机制；跃击免伤、盾链与反击，各派生攻击需单独确认形式 |

这些是核心路径，不能替代每个派生攻击的声明。例如战士飞刃在 AttackSystem 以 melee 结算，不能因视觉上飞出去就当 ranged；导弹余烬明确保留 ranged，也不能把所有 dot 强制改成 other。

**持续命中不等于 DoT。** 激光用 hit + continuous 保留浮点且允许受限暴击；dot 必须浮点且禁暴。当前通过 hurtEnemy 发 DoT 时，调用方还要显式关闭普通命中触发、连锁和吸血；仅写 `kind:"dot"` 不会替你关闭全部副作用。

## 6. 结果、快照与统计不能省略

- 区分原始伤害、计算器结果、最终应用伤害、实际 HP 损失。吸血应使用该玩法明确规定的实际损失/预算，不以溢出伤害回血。
- 普通伤害报告 dmgBy 可含溢出伤害；元素使分项、武器预算和领域主分量治疗存在各自口径，不得重复计入总伤害。
- 发射快照、引爆快照、接触实时读取和每跳实时读取是不同机制。复制映射避免快照被实体后续修改污染；不以“统一”名义改取样时刻。
- hurtEnemy 内会执行死亡处理；旧燃烧和元素 DoT 的死亡由调用侧处理。Boss 每次扣血后的阶段同步都要保留。
- 重算属性需保护当前 HP、盾层、冷却和运行状态；“基础值被重建”不能顺便回满资源。

## 7. 本轮整理结果与保留边界

| 事项 | 当前实现 | 后续新增时怎么处理 |
|---|---|---|
| 历史文档/注释 | 当前开发入口已同步；旧 Foundation / 图解为历史教学 | 先读当前指南与 skill，不依据旧阶段文字判断实现 |
| 技能增伤 | HitOptions / PlayerHitOptions / components / 公共 DoT 已透传 skillId；怪物行动有稳定键 | 主/派生逐项声明键与继承权限；只配置映射仍不会自动选择技能 |
| 玩家映射来源 | AttributePoint/AttrDef 携带 key；PlayerCombatSources 支持 resistance/type/form/skill 四族 | 同次重建、稳定键所有权；来源失效清旧值，不向标量解析塞缺 key 的族名 |
| 全部攻击分类 | attackProfiles 覆盖七武器主/派生与全部敌方技能/弹丸/接触/地面；所有实际受击调用有明确 type/form/skillId | 新路径登记声明并执行静态核对；时变属性不改变技能身份 |
| 纯伤害公式 | 射手距离/发射/百分比生命/衰减、旧兼容武器、战士挥砍/居合/跃击/波、元素直伤/反应/链/DoT 均由 DamageMath 形成 raw；条件触发与状态仍在系统层 | 保留原运算顺序；已有职业数据仍拥有其参数，不复制一套系数；新增/改公式按统一入口处理 |
| DoT应用 | 旧燃烧/焦土/元素 DoT 共用 applyEnemyDotDamage；连续武器保留 hurtEnemy 触发预算 | 纯 DoT 与连续命中按语义选择；最终倍率不能再乘一次，死亡仍由原调用侧执行 |
| 派生伤害有历史继承口径 | hurtEnemy 连锁沿用上一击应用伤害再发起命中 | 保留已有语义；新派生声明继承 raw/结算值/实际 HP 损失中的哪一个，避免无意二次增伤 |
| 抗性展示 | RESISTANCE_TYPES 从注册表派生；通用/领域面板和敌人图鉴复用，图鉴护甲参数读取 combatBalance | 新伤害类型仍核对专属飘字/状态；抗性清单无需维护第二份固定三元素表 |

普通命中的主/真实分组取整、旧 DoT 左结合浮点乘法、runHighestHit 原记录时点、领域主分量吸血口径，以及历史连锁继承已应用伤害均保留。skill 固定新增声明与接线核对；本轮编译验证不能证明自然玩法、性能或平衡已验收。

## 8. 本次整理的完成范围

现有实际受击路径已登记并接入公共应用，玩家映射属性与技能键已贯通，怪物基础防御及全部图鉴引用已核对，纯伤害公式与状态编排分开，skill/指南/静态命令已同步。六反应中超导/霜缚以链与控制为主；v176 起分别补 45%/凝冰层与 40% 的反应伤害，不再是无伤反应；保留的旧激光/导弹接口也计入清单，未恢复其入池。

运行 `node scripts/audit-combat-contracts.mjs` 可重新核对，带 `--write` 更新清单。此范围不包含重新平衡、控制系统重设计、浏览器/自然试玩或性能验收，也不要求把几何、计时和运行状态全部搬进纯伤害计算器。
