## 1. 素材与动作

- 认可的17张16×16/24×24静态PNG、像素原稿、Boss八姿态图集均保持原样。
- `MonsterAnimationArt.ts`从认可的像素矩阵生成17套、204帧原生动作。每套12帧槽位：原始、两个步态、两个蓄力、两个释放、恢复、受击、两个通道、破盾；各物种按自身轮廓处理翼、触须、腿、前壳、鼓槌与黏体形变。
- 帧格为原始尺寸+8像素透明留白（普通24×24，精英32×32），共享中心锚点；帧0等于原PNG居中加4像素透明边。生成器逐像素检查首帧锁定并记录SHA-256。
- 正式条带位于`public/assets/monsters/animation`。`MonsterAnimation`由Scene持有，只读真实位移、AI阶段、控制状态和释放事件，在固定步采集；素材失败时退回认可的静态图。
- Boss动画、特效与加载器已恢复至v167提交状态；原版八姿态与技能图集继续正常使用，本批只改普通怪和精英。

## 3. 运行时边界

- Core只在真实接触尝试、发弹、引爆、分裂、吐网、钻出、冲锋结束、词缀释放与新技能释放处写入`enemyVisualEvents`；队列上限192，记录模拟时间、来源与落点，不消耗随机数，也不参与伤害判断。
- `EffectsSystem`按模拟时间回收，换波、重开、返回开始、死亡/DEV复活清理。清场转收球时保留已释放的短尾迹，使最后一只怪物的爆炸/分裂正常播完。
- `MonsterFxRecipes.ts`是运行时与离线预览共用的纯几何配方。`MonsterVfx`只读状态，复用`PixelPainter`的Graphics/Image池，无额外生产RAF或输入监听。
- 预警半径、通道长度/宽度和落点继续读取原战斗配置与事件；点到线段的圆端与预警一致。新效果不写HP、速度、控制计时或随机序列。
- 旧敌人攻击绘制从`draw.ts`移出；`EnemySkillRenderer`保留兼容导出。Boss继续使用原版绘制器和原版技能图集加载流程。
- 暂停时模拟时钟停止，动作和效果保持；冻结、霜牢、眩晕和领域硬控时冻结本体动作采样，实际取消的通道不会继续绘制。

## 4. 重建和预览

在Node24与项目既有依赖/Pillow环境下运行：

```powershell
node scripts/build-monster-animation-assets.mjs
node scripts/build-monster-motion-preview.mjs
python scripts/export-monster-motion-preview.py
```

- `docs/previews/monsters-v168/index.html`：自包含23段素材演示，可暂停、0.25×/0.5×/1×/2×播放、拖动时间，筛选小怪/精英及切换预警轮廓。
- 同目录`all-attacks.gif`与`contact-sheet.png`：共享绘制配方导出的48帧离线总览。
- 离线动作编排会归一化展示位置与比例，不能用来判定正式命中范围、实际TTK或自然对局难度；正式范围仍由战斗配置决定。中间绘制指令位于被Git忽略的`output/monsters-v168`。
