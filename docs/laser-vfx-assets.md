发射口释放复用对应 pulse 的局部帧，两个释放类型共用结构与锚点。64×32 脉冲画布包含居中的 32px 源图内容及透明留边；不是把源图横向拉伸到 64px。每帧的实际可见范围单列在 metadata 的 `frames[].visibleBounds`，不能把画布宽度当成命中宽度。

`laser.metadata.json` 包含帧名和顺序、完整矩形、固定锚点、每帧秒数 / 归一化时间、循环标记、参考束宽 4px、颜色、处理方法、条带 / 图集 / 源图 SHA-256。`assets/vfx/laser/SHA256SUMS.txt` 还包含正式 JSON、源图和提示词的哈希。

正式色板只使用当前 `palette.ts` 的 `iceDeep #1a9fd4`、`iceCyan #57e6ff`、`bone #e8e8f0`、`white #ffffff`、`gold #ffd24a`。PNG alpha 只有 0 / 255；连续强度、交叉过渡和余光由绘制 alpha 控制。金色用于满焦点圆环和真实熔断释放，65% 聚能阶段仍为青白，避免暗示必定熔断。

整张生成表只使用一个共同的 8×8 源网格和 32×32 逻辑采样网格，不按单帧包围盒裁剪、缩放或重新居中。共享的固定包络清除源图杂边；画布和锚点不随动画变化。第二稿束身采用静态低对比切片，移除白色材质芯和每 32px 的亮截面；两端复制普通内部列以建立周期边界，亮芯改由一条连续绘制指令负责。禁止用静态贴图的自动裁剪居中脚本重新处理这些帧。

PNG 参考像素比例为 1px / 世界单位。实际 `width` 保留在低亮的连续包络中；主要青色主体只占实际宽度的 44%—48%，白芯为 `max(1,width×0.12)`。材质纵向比例基础为 `width/4×0.28`，在末段压紧 15%，聚焦时再轻微收紧 5%；透明度由 focus 在 0.10—0.22 之间变化。它只提供内部细节，不独立决定轮廓。

## 第二稿的聚焦与裁切接口

`u=elapsed/duration` 只决定点亮、稳定、末段聚能 / 收束和结束；每束 `line.focus` 独立决定输出强度。持续阶段的白芯 alpha 从 0.60 到 1.00，青色主体 alpha 从 0.22 到 0.38，宽度从实际宽度的 48% 轻微收紧到 44%。发射口 alpha 从 0.50 到 1.00，比例从 `sqrt(width/4)×0.62` 收紧到 `×0.50`；点亮和正常结束仍叠加自身阶段包络。

`contacts` 现在保留 `{x,y,target:boolean}`：`target` 表示当前束确实命中其锁定目标。只有 `target:true` 接触点随 focus 增强热点和火花；普通贯穿点使用固定 0.35 比例 / 0.35 alpha。锁定命中火花比例从 0.45 到 0.85、alpha 从 0.55 到 1.00；满焦点增加约 5×4px 包络内的小白热点。束端固定低亮装饰，不抢过命中点。以上均为表现参数，不是伤害倍率。

sprite 指令增加 `cropX?:number`，与 `cropWidth` 一起使用。全束共享 `sourceX=(-floor(time×80) mod 32 +32) mod32`，即向前 80px/s、1px 量化的连续滚动，不再每 50ms 跳 4px。所有段的 alpha 相同，没有逐 tile 淡入淡出。材质总显示长度只做一次 `round(length)`，允许与真实末端相差不超过 0.5px；碰撞、连续主体和真实端点保持原坐标。

第一块从 `cropX` 开始读取至切片末端，后续从 0 开始读取，最后一块按剩余长度裁切。共享的 `laserSpriteCrop()` 对源偏移 / 长度执行整数 floor、非负 clamp 以及源宽上限约束。三个后端约定一致：裁切内容的左端绘制在指令目标起点（减公共 anchor），不额外保留被裁掉部分的水平空间。

- Canvas 从 `rect.x+cropX` 读取，直接画到当前目标起点。
- Phaser 使用 `setCrop(cropX,0,cropWidth,height)`，并把 Image 位置沿束轴反向补偿 `cropX×scaleX`；旋转时 X/Y 均补偿，避免横向和斜向出现间隔。
- Pillow 使用相同 floor / clamp 源区域，裁出子图后按共同 anchor 变换；不再把末块 `ceil` 成额外一列。

v137 桥接器在熔断后读取真实脉冲几何、种类和时刻，同时保留上一帧的目标 / 接触点 / 聚焦强度。真实熔断事件将视觉 focus 确认为 1，避免被战斗侧已清零的 aim.focus 拉暗；战斗清零逻辑不变。45ms 材质交叉过渡共用一条连续白芯，宽度和 alpha 从释放前强度平滑进入峰值，避免两条半透明白芯叠画产生中间暗谷。新轮开始后旧脉冲的叠加权重从 1 在 80ms 内平滑降至 0.4，按新轮 elapsed 计算，取消原 age=0.05 时的跳变。

## 完整时间设计

主束使用真实输入的 `u=elapsed/duration`。1.0 和 1.3 秒都经过同样的四段，不把帧数绑定到固定 1.3 秒，也不使用焦点代替周期进度。

1. **0—8% 点亮**：发射口的八帧建立聚光；连续束芯立即可见，不增加攻击前摇。
2. **8—65% 稳定照射**：连续白芯、平铺流动纹理、束端、局部错相火花持续变化，无整条束频繁闪断。
3. **65—85% 聚能**：发射口前四帧凝聚，保持青白；输出亮度仍由 focus 决定，周期推进不会把未命中的束伪装成满聚焦。
4. **85—100% 收束**：装饰纹理向内压紧，发射口后四帧收束。预期无脉冲时外缘同时降低亮度；实际碰撞宽度的连续指引保持。
5. **结束后**：按真实释放事件选择普通消散 / 青白坍缩 / 金白熔断。保留最后照射姿态并在约 45ms 内与释放交叉过渡，避免清主束后另起一个孤立动画。

两种脉冲的 8 帧时长为 `[22.5,22.5,25,30,35,35,35,35]ms`，合计 240ms：前 45ms 快速展开，45—75ms 短峰值，余下 165ms 尾迹逐渐退出。刚触发即沿整条实际轴线给出亮芯和命中提示；移动的局部亮头从 35ms 后出现，只代表能量余波。这个 240ms 只属于表现，**不延长回充，不延迟下一次攻击，不再次结算伤害**。新一轮起束后旧余光按 80ms 平滑降低叠加强度，方向和位置仍锁定旧快照。

没有预先锁定金色释放。主束末段的压紧使用共同青白结构；焦点失效可自然进入普通结束 / 坍缩，最终释放种类始终由真实事件决定。

## 可复用接口

代码位于 `src/game/rendering/vfx/laser/`：

| 文件 | 职责 |
| --- | --- |
| `laserAssets.ts` | 由素材构建脚本生成的 clip 帧表，不手工维护 |
| `LaserVfxPlayer.ts` | 纯表现时间采样、阶段、释放快照、绘制指令和圆环，零 RAF / 定时器 / RNG |
| `LaserV137Bridge.ts` | 对当前 v137 的只读兼容采集，不写 GameCore |
| `LaserVfxPhaser.ts` | atlas 加载示例、可复用 Image / Graphics 池和生命周期 |
| `LaserVfxCanvas.ts` | 离线 HTML 使用的 Canvas 绘制后端，消费相同指令 |
| `LaserVfxDemo.ts` | 独立素材演示的确定性路径与事件，不属于战斗规则 |

`LaserVfxPlayer.update(frame, releases)` 返回 `LaserVfxCommand[]`。frame 包含模拟 `time`、周期 ID、阶段、真实照射 `elapsed/duration`、各束的世界坐标 / 宽度 / 焦点 / 目标 / 实际命中点，以及仅用于预收束的 `expectedPulse`。`LaserVfxRelease` 包含唯一 ID、真实触发模拟时间 `at`、真实种类和发出时的整条 beam 快照。

播放器深复制释放几何、目标和命中坐标。`remaining/total` 改为回充值、下一轮换目标或玩家移动都不会拖动旧脉冲。按同一模拟时间重复调用不会推进动画；时间回退会清理内部状态，重开 / 场景销毁仍应显式 reset / destroy。

圆环按 `target.id` 去重，采用所有当前束的最高 `focus`，半径为 `target.radius+3`。从上方开始按 0—1 连续画弧，未满为青色，满值为当前色板金色；每目标只保留两颗沿圆周运动的 1px 微光点。它不写目标、不产生伤害、不更改索敌。

## v140 正式游戏接入

开始游戏 → 射手 → 激光即可使用。图集在 GameScene.preload 中通过现有 Phaser Loader 加载，使用 BASE_URL 兼容静态子路径部署；加载失败时保留程序化回退。

| 接线位置 | 当前职责 |
| --- | --- |
| GameScene.preload | 加载正式 laser.atlas.png / JSON |
| GameScene.captureLaserAnimation | 每个固定模拟步之后采集真实光束、焦点与释放；绘制前再观察一次 UI / DEV 重置和暂停状态 |
| LaserV137Bridge | 只读采集，保留逐束释放前 focus / 目标 / contacts；真实熔断确认满焦点，真实脉冲几何和时间保持 |
| LaserVfxPlayer | 按模拟时间产生用户认可的连续细束、圆环和 0.24 秒释放指令 |
| LaserVfxPainter | 在原 drawLaser 位置消费指令，复用 PixelPainter 的世界图像 / Graphics 池、相机和绘制深度 |
| PixelPainter.spriteFrame | 图集帧、非等比缩放和裁切；普通 sprite / spriteRot 复用前也清除 crop，避免裁切状态污染其他精灵 |
| LaserRenderer | 新动画就绪时只补原余辉 / 折光残像 / 紧急散射；跳过旧主束、旧脉冲、四角框和发射口，资源条照常保留 |

本项目不使用固定 baseDepth 的独立 PhaserLaserVfxView，以免穿过现有动态世界 / HUD 层级；该类保留为其他场景的标准 Phaser 接入参考。实际游戏所有激光图像使用既有 PixelPainter 对象池，随现有顺序绘制于伤害飘字与 HUD 之前。

capture 必须保留在每次固定步之后，不能只在一帧末尾采集。绘制前的额外采集使用相同模拟时间，不推进动画，只观察无固定步的暂停 / 返回开始界面 / 重开 / DEV 清理等状态变化。Scene shutdown 会清空桥接器、播放器和待绘指令；图像由既有 Scene / PixelPainter 生命周期管理。

正式接入仍采用只读兼容桥：普通结束使用最后一个固定步的主束几何，脉冲接触点从前一步读回，真实脉冲位置 / 方向 / 时刻来自实际 aux 快照。这是已有模拟接口的精度边界，未增加攻击等待、重复伤害、随机数或第二套时钟。

## 复现与来源

已有 Node / 项目依赖时：

```powershell
Set-Location 'E:\AllProjects\pixel-rogue-laser-animation'
node scripts/build-laser-vfx-assets.mjs
node scripts/build-laser-vfx-preview.mjs
# 可选 GIF / 检查图导出，使用本机已有 Python / Pillow：
python scripts/export-laser-vfx-preview.py
npm run typecheck
npm run build
```
